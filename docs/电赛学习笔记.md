## GPIO 和时钟——每次必踩的坑

STM32 所有外设默认时钟都是关的。**配置任何东西之前，第一件事永远是开时钟。**

`c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);  // GPIOA 在 APB2
RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);   // TIM2 在 APB1
`

哪个外设在哪个总线上需要查手册，记不住。大概规律：
- APB2：GPIO、USART1、ADC、TIM1、AFIO
- APB1：TIM2/3/4、USART2/3、I2C、SPI

四种 GPIO 模式：

| 模式                   | 干嘛用                   |
| ---------------------- | ------------------------ |
| 推挽输出 (Out_PP)      | 点 LED、PWM 输出         |
| 开漏输出 (Out_OD)      | I2C（需要外部上拉）      |
| 上拉输入 (IPU)         | 按键（默认高，按下拉低） |
| 浮空输入 (IN_FLOATING) | USART RX 引脚            |

**踩坑**：STM32 是 3.3V 器件，IO 口不能直接接 5V。刚学的时候把一个 5V 模块直接怼到 PA0 上，闻到焦味才反应过来。还好没烧。

## 串口 USART

最常用的调试手段。先把 printf 重定向搞定：

`c
int fputc(int ch, FILE *f) {
    USART_SendData(USART1, (uint8_t)ch);
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
    return ch;
}
`

配好这个之后就能用 printf() 往串口打日志了。

DMA 接收方案是在比赛里才用上的。一开始用轮询收 OpenMV 的数据，老是丢帧。后来改成 DMA 循环缓冲 + IDLE 中断，每次 IDLE 中断触发就处理整帧数据。IDLE 中断的 SR 和 DR 读取顺序有讲究——必须先 SR 后 DR，反了下一个 IDLE 就不会触发了。翻了好久 datasheet 才发现。

## 定时器

F103C8T6 的 APB1 最高 36MHz，但如果 APB1 分频系数不是 1，定时器时钟会乘 2，所以 TIM2/3/4 实际是 72MHz 的。

**舵机 PWM (50Hz)**：
- TIM3, CH2, PB5
- 预分频 72-1 → 1MHz (1us per tick)
- 周期 20000-1 → 20ms
- 脉宽 500~2500us 对应 0~180 度
- 这个配置在比赛代码里用了，调了很久才稳定

**电机 PWM (20kHz)**：
- TIM4，四路通道，PB6~PB9
- 预分频 36-1 → 2MHz
- 周期 100-1 → 20kHz
- 20kHz 以上人耳听不到电机啸叫

**1ms 计时 (TIM2)**：
- 预分频 7200-1，周期 10-1
- 72M/7200/10 = 1kHz，每毫秒进一次中断
- 中断里只做了一个 g_TrackTimeMs++，用来记录循迹时间

## 串口 DMA + IDLE 中断（比赛重点）

这是比赛里处理 OpenMV 数据接收的核心方案。

**接收链路**：
1. DMA1_Channel5 循环模式，128 字节缓冲
2. USART1 IDLE 中断检测帧结束
3. 主循环 20ms 跑一次 Serial_Task()，消费缓冲区里的字节
4. 逐字节喂给状态机解析 ASCII 帧

**帧格式（OpenMV 发的）**：
- X+0025\r\n → 正常坐标，25mm，正方向（左侧）
- X-0018LOST\r\n → 短暂丢失，Kalman 预测坐标
- X+LOST\r\n → 丢了一段时间，只剩方向
- lost\r\n → 彻底丢了

状态机有 12 个状态，逐字节走。写得比较笨但能用，容错靠 ResetAndReplay 机制——碰到意外字节就重新开始解析，不会卡死。

## PID 控制

比赛里用了两套 PID，都是位置式的，整数运算（都乘了 100 再算，最后除回来）。

公式就是：输出 = Kp*误差 + Ki*积分 + Kd*(误差-上次误差)

**静止模式（球在管道上跑来跑去）**：
- Kp=80, Ki=0, Kd=200
- 目标：0 → +50mm → -44mm，最后停在 -44mm
- Ki 设为 0 是因为积分项在球控里容易低频振荡
- Kd 比较大是因为球容易冲过头，要大刹车

**循迹模式（车在跑，球锁在用户放的位置）**：
- Kp=70, Ki=0, Kd=150
- 比静止模式参数小一点，因为车本身的震动就是扰动，D 太大会追着噪声跑

**目标限速**：切目标的时候（比如从 +50 跳到 -44），瞬间误差 94mm，PID 的 D 项会炸。解决办法很简单——不让目标直接跳变，每个周期只让实际跟踪的目标靠近 3mm，把大阶跃拆成 30 多个小步。

调 PID 的过程：先只调 P，能动起来再加 D 压过冲，最后看情况补一点 I。D 不能太大，OpenMV 的坐标有 ±1~2mm 的抖动，D 太大会把噪声放大。

## 中断与 NVIC

用的 NVIC_PriorityGroup_2，2 位抢占 + 2 位响应。

TIM2 中断（1ms 计时）和 USART1 中断（IDLE）优先级都设的 1/1。两个中断不太会同时触发，所以没细调优先级。

volatile 关键字：在中断和主循环之间共享的变量必须加 volatile。g_TrackRunning 和 g_TrackTimeMs 都加了。不加的话编译器优化可能会把主循环里的 while(g_TrackRunning) 优化成死循环。

---

## ADC

F103 的 ADC 是 12 位的，0~4095 对应 0~3.3V。

比赛里没用 ADC。本来打算做一个电池电压检测，根据电压补偿舵机输出（电压低了舵机响应变慢，需要加大 PID 输出）。没来得及做，这也是比赛翻车的原因之一。

## OLED (SSD1306)

0.96 寸，I2C，地址 0x78。软件模拟 I2C 用的 PB10(SCL) 和 PB11(SDA)，开漏输出。

F8x16 字体，4 行 x 16 列。显示用了一个取模的字库，存在 Flash 里。

两种模式下的 OLED 显示：
- 静止预演：第 1 行球坐标 "X:+050"，第 2 行状态 "ST:normal"
- 循迹：第 1 行 "Time:" + 计时，会更新为分:秒.十分之一秒

## 位操作用法（记不住老查）

`c
REG |= (1 << n);      // 第 n 位置 1
REG &= ~(1 << n);     // 第 n 位清 0
REG ^= (1 << n);      // 第 n 位翻转
bit = (REG >> n) & 1; // 读第 n 位
`

## C 语言容易忘的

- `volatile`：中断和主循环共享的变量必须加
- `static` 局部变量：只初始化一次，函数退出后值保留
- `extern`：别的 .c 文件里定义的全局变量，在头文件里声明用

## 杂项

- F103C8T6 没有硬件 DAC。需要模拟输出的话用 PWM + RC 滤波
- C8T6 是中容量芯片，启动文件是 startup_stm32f10x_md.s，选错程序跑不起来
- 比赛用的编译器是 ARM Compiler V5.06，-O2 优化

## 比赛踩坑记录

1. OpenMV 串口数据偶尔会丢帧。排查了很久发现是主循环里 Delay_ms(20) 阻塞太久，DMA 缓冲区里的数据来不及消费。改成每个周期先调 Serial_Task() 消费数据再做别的就好了。

2. 舵机一开始用板载 3.3V 供电，完全带不动。MG996R 至少要 5V/2A 的独立电源。

3. 红外循迹阈值在不同的光照下完全不一样。实验室调好的参数到比赛场地不认线了。以后一定要做光照适应性测试。

4. 电池电压对舵机影响很大。满电 6V 和快没电的 4.8V，舵机响应速度差别很大。PID 参数是按满电调的，电压下降后就不准了。
